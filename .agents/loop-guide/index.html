The loop is size-gatedBig work is aligned before code. Small work goes straight in. Both end the same way.

Is "done" clear and the change contained?
NO · big, ambiguous, crosses packages
/grill-with-docs→ /to-spec→ /to-tickets→ sub-issues · ready-for-agent→ /almalgo-mode × each ticket
YES · a bug, a labelled issue, a contained change
/almalgo-mode→ read AGENTS.md · GLOSSARY · ADRs→ pick 1 of 9 playbooks→ copy its steps into the todo list
TOO BIG for one session · many open decisions
/wayfinder→ map of decision tickets→ one decision per session→ /to-spec

Autonomy & subagents

✅ Just do it

  • Edit, commit on a feature branch
  • Run the local stack
  • Open a ready PR when asked
  • Comment on issues
  • Settle "which approach" by prototyping, not asking

🛑 Always ask first

  • Force-push shared branches, push to main
  • Wiping a database / deleting data you didn't create
  • Merging (unless you said merge/land/ship)
  • Deploys, hosted envs, prod data
  • Labels, milestones, repo settings
  • Messages to people outside the session

🤖 Subagents

  • almalgo-agent (.cursor/agents/) reads almalgo-mode first
  • model: inherit, no pinned models
  • Fresh subagent per piece of work, full brief
  • Parallel editors each get a worktree
  • You own the output: read the diff, write your own summary
